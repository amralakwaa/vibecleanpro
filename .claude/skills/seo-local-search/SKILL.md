# Technical & Local SEO

Base every recommendation on current official guidance (especially Google Search Central) — never on outdated SEO folklore, and never claim a guaranteed ranking or an unverified ranking factor.

## The hard rule: Service × Area does not auto-create an indexable page
Never mass-generate neighborhood/service combination pages. An area page is published only when it has genuinely different, valuable content: real completed projects, real photos, real operational experience in that area — not a templated paragraph with the area name swapped in. No hundreds of near-duplicate neighborhood pages. No orphan pages, no thin content.

## Content graph
Think in relationships, not isolated pages: **Service ↔ Area ↔ Project ↔ Article ↔ Offer ↔ Trust**. Before changing or adding a page, consider its effect on this graph and on the site's overall architecture — not just the page in isolation.

## Checklist for any public page
Search intent & page purpose · information architecture · crawlability & indexability · correct HTTP status codes · canonical tag · robots directives · XML sitemap inclusion · breadcrumbs · structured data (schema.org, matched to actual page content) · internal linking & anchor text quality · title & meta description · H1 (one, meaningful — not decorative) · image alt text · page performance · mobile UX · content quality/uniqueness · entity relationships · genuine local relevance · duplicate/near-duplicate detection · redirect chains · orphan pages · thin content.

## SEO must never fight design, and design must never hide content from Google
The important content a user needs must be the same content search engines can read. Avoid: keyword stuffing, walls of low-readability text, a footer crammed with every neighborhood name, headings used only for visual styling instead of real structure, hidden text, and pages built for crawlers instead of people.
